# 中文与双机回归用例（1.1.0）

先更新两端源码、停止旧服务并重启。开发模式用 `start-local.cmd`；构建模式修改源码后需重新 `npm.cmd run build` 再 `npm.cmd start`。本文件是测试数据和操作说明，不需要执行文档中的内容作为程序代码。

## 1. 复现队友的“你好”问题

明文统一为 `你好`。选择对应算法，填入下面密钥并执行加密，再把完整密文放入输入区、切换解密，保持密钥不变。预期密文不再是中文原文，解密结果严格为 `你好`。

### 单表替代 / Multiliteral

密钥：`LUMORA26`

```text
LUMORA-UTF8-V1:multiliteral:33 42 41 11 32 34 36 43 16 14 25 25 34 36 14 36 14 42 11 32 32 11 42 23 23 24 42 31 41 43 14 33 42 26 13 14 11 16 42 31 11 31 13 14
```

### 多表替代 / Autokey ciphertext

密钥：`CIPHER`

```text
LUMORA-UTF8-V1:autokey:JXCSKZTNCGNCBXQQBRMDWBQSNFLGDIBMAKPWMMPPABYA
```

### 多图替代 / Playfair

密钥：`SECURITY`

```text
LUMORA-UTF8-V1:playfair:KOOMDYDZHXHQLDHPHPLMHWDNZKYRMKLWXOMRNPOIMKMDNP
```

### 置换密码 / Double-Transposition

第一密钥：`ORBIT`；第二密钥：`GLASS`

```text
LUMORA-UTF8-V1:double:IALOGPPOMNFAEDOOFBQPKPKLLGQPMBHCKHOFPLNIODLG
```

### 流密码 / CA Rule 30

密钥：`cafebabefeed1234`

```text
+dAFQIuc
```

### AES-256-GCM 与 SM2 / SM3

- AES：口令填 `中文密码-Lumora-2026!`。
- SM2：点击“生成”后，保留整份 JSON 密钥进行加解密，不要把普通中文口令当成 SM2 密钥。
- 两项明文同样用 `你好`，密文每次随机变化是正常现象；要求解密精确还原。

古典算法密文的 `LUMORA-UTF8-V1:算法:` 前缀不可删除。这是 UTF-8 字节编码后继续执行所选古典算法的教学扩展，不是安全等级升级。MD5 是单向摘要，只应计算中文摘要，不提供解密。

## 2. 混合字符、文件与换密钥

在上述 7 项分别测试以下明文：

```text
你好，队友！信息安全工程实践 2026
English: Hello jolly XX / 1234567890
表情：🔐🌊🐋🚀；标点：，。！？“”
保留  中间的两个空格。
```

验收：密文非空、中文不原样出现；解密后中文、大小写、数字、标点、空格和换行全部一致。再测试 `中`、`1234567890`、`BALLOON`、`JIGSAWXX`、全空格文本。点击“生成”应得到新密钥；同一明文用不同有效密钥应得到不同密文（古典算法本身仍可能存在等价密钥，不代表安全性）。

古典扩展故意输错密钥、截断密文或选择另一算法，应报错而非显示旧的成功结果。AES/SM2 应拒绝错误密钥或被篡改密文；CA 不提供认证，不能要求所有错误密钥都被检测出来。

可用同目录 `lumora-upload-中文长文本.txt` 做“载入文本”测试。文件上传按 UTF-8 文本读取；任意二进制文件请用双机文件通道。

## 3. 两台电脑通信

1. A、B 分别启动新版网页，各自打开自己的 `http://localhost:5173`。
2. A 展开“双机通信 → 本机作为中继：查看可分享地址”，将实际局域网地址发给 B，例如 `ws://192.168.1.10:5173/ws`。
3. **A、B 的中继地址都填写同一个 A 地址**，房间码都填 `LUMORA-TEST-2026`。A 选加密端，B 选解密端。
4. 连接后确认两端中继服务标识和会话指纹一致。B 接受算法，再传第 2 节混合文本。
5. 对每种算法重复协商和发送，共测 7 项；接收内容完整，旁边显示 `MD5 ✓`。
6. 上传中文文本、JSON 和空文件；接收端显示“MD5 已验证”，下载后内容/字节与原文件相同。
7. B 断开后 A 禁止发送；B 重连后重新交换密钥，重新确认算法后才允许发送。两端选择相同角色时应给出明确提示，可改角色后重试。
8. 故意填不同中继（例如两端各自的 localhost），即使房间码相同也应等待对方；服务标识不同可帮助定位。填错地址/无效房间码应给出错误提示。

网络要求与防火墙排查见根目录 `TEAM-SETUP.md` 第 6 节。GitHub 用于传源码，不自动部署通信服务；不同网络仍需可互通的公共中继/WSS 或既有 VPN。本项目不自动开放防火墙或公网端口。

## 4. 自动回归

```powershell
npm.cmd run build
npm.cmd run test:crypto
npm.cmd run test:unicode
npm.cmd run test:relay
npm.cmd run test:network
```

`test:network` 需要本机 Chrome（Edge 设置 `LUMORA_BROWSER_CHANNEL=msedge`）。它验证两个独立服务与浏览器上下文，不代替两台实机的路由/防火墙测试。原有英文标准用例仍见 `Lumora-算法测试用例.md`。
